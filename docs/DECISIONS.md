# Architecture & Technical Decisions (DECISIONS.md)

### ADR 001: 100% Client-Side Storage with Dexie IndexedDB
- **Context:** An IPTV playlist can easily contain 10,000–100,000 channels and megabytes of XMLTV EPG data.
- **Decision:** Use Dexie.js to store playlists, channels, groups, programs, favorites, and watch history in IndexedDB with compound indexes on `playlistId`, `groupId`, and `channelId`. Tiny settings remain in `localStorage`.
- **Consequence:** Zero server cost, total user privacy, offline resilience, and fast query execution.

### ADR 002: Spatial Navigation Engine Abstraction
- **Context:** Remote controls on Smart TVs require deterministic 2D directional navigation.
- **Decision:** Wrap `@noriginmedia/norigin-spatial-navigation` behind our internal `src/shared/focus` module (`useFocusable`, `FocusZone`, `FocusScope`).
- **Consequence:** UI components are decoupled from any specific navigation library and remain unit-testable and swappable.

### ADR 003: Multi-Engine Video Player Adapter
- **Context:** IPTV streams arrive as HLS (`.m3u8`), MPEG-TS streams (`.ts`), or standard MP4/WebM files. Different browsers/devices support different codecs natively.
- **Decision:** Define a `PlayerEngine` interface with three concrete adapters: `HlsPlayerEngine` (using `hls.js`), `MpegtsPlayerEngine` (using `mpegts.js`), and `NativePlayerEngine` (HTML5 `<video>`). Fallback order is automated with configurable preference.
- **Consequence:** Maximum playback compatibility across Chrome, Safari, Android TV WebView, and Tizen/webOS.

### ADR 004: CORS & Mixed-Content Strategy
- **Context:** Modern browsers enforce CORS and block mixed content (HTTP streams on HTTPS origins).
- **Decision:** Client-side detection of network fetch and playback failures with rich diagnostic modal explaining the root cause. Provide a user-configurable proxy URL template (e.g. `https://my-proxy/?url={url}`) without shipping an unmaintained third-party public proxy. Also bundle legal HTTPS test streams in the Demo mode.

### ADR 005: Client-Side Virtual Keyboard & Remote Text Entry
- **Context:** Android TV browsers sometimes fail to trigger OS soft keyboards on text inputs without user interaction.
- **Decision:** Provide a built-in 10-foot virtual keyboard with fast URL buttons (`http://`, `https://`, `.m3u8`, `.com`, `/`, etc.) alongside native input support.

### ADR 006: Synchronous Spatial Navigation Engine Initialization
- **Context:** `@noriginmedia/norigin-spatial-navigation` requires `init()` to create its `layoutAdapter` before any component calls `addFocusable`. Because child component `useEffect` hooks run before parent `useEffect` hooks, initializing inside `App.tsx` caused `this.layoutAdapter is undefined`.
- **Decision:** Call `initFocusEngine()` synchronously at module load time in `src/shared/focus/spatial.ts`, explicitly at the entry point in `src/main.tsx`, and as a synchronous pre-check in `useFocusable`.
- **Consequence:** Eliminates runtime race conditions during initial mounting and guarantees `measureLayout` always has a valid adapter.

### ADR 007: Resilient Multi-Engine Fallback, In-Player CORS Proxy Presets & Sub-Request Proxying
- **Context:** IPTV providers stream across disparate container formats (M3U8, MPEG-TS, MP4) and frequently lack CORS headers or use unencrypted `http://` streams that modern browsers block under Mixed Content security rules on HTTPS sites. In addition, when an initial engine (e.g. native HTML5 video or Hls.js) failed on unsupported formats (such as raw MPEG-TS in Chromium), the player previously retried the same failed engine repeatedly instead of progressing down the fallback chain. Furthermore, Hls.js proxies only fetched the master manifest through the proxy while sub-requests for fragments and keys still hit CORS errors.
- **Decision:**
  1. Implement deterministic multi-engine startup fallback in `PlayerManager` (trying `hls` -> `mpegts` -> `native` sequentially before declaring fatal failure).
  2. Implement sub-request proxying in `HlsPlayerEngine` using a custom `Hls.DefaultConfig.loader` extension that ensures fragment, playlist, and key URLs are routed through the configured proxy.
  3. Introduce 1-click CORS proxy presets (`corsproxy.io`, `allorigins`, `codetabs`) selectable both in Settings and directly inside the stream error overlay and diagnostic modal.
  4. Replace expired/403 test streams in the public demo playlist with verified, high-availability public feeds (Deutsche Welle HD, Apple BipBop, Mux adaptive test) and automatic IndexedDB migration.
- **Consequence:** Zero remote-typing friction for TV users encountering CORS/mixed-content errors, seamless format fallback across Chromium/Safari/TV browsers, and 100% working verified demo playback.


### ADR 008: Bug-hunt behavioural defaults
- **Context:** The bug-fix pass (see `docs/BUGS.md`) surfaced several places where the existing code was ambiguous or conflicted with the spatial-navigation library. Each needed a safe default rather than a product decision.
- **Decision:**
  1. **BACK is single-dispatch.** The global back-handler stack is driven by exactly one module-level window listener (`dispatchBack()`). Components never pop the stack themselves. This guarantees one layer per key press regardless of how many `useTvInput` instances are mounted.
  2. **Overlays own the D-pad.** When the player controls overlay or the stream-error overlay is visible, NAV_*/SELECT are yielded to the spatial-navigation engine; the player only keeps media/info/digit/color shortcuts. Auto-hide is paused while navigating.
  3. **HLS media recovery is bounded.** `HlsPlayerEngine` attempts in-place recovery twice (`recoverMediaError`, then `swapAudioCodec` + `recoverMediaError`) before reporting fatal. Network errors are never recovered locally: `PlayerManager` alone owns fallback and exponential backoff.
  4. **Async player callbacks are generation-gated.** `PlayerManager` increments a session token per load; stale `init`/error/success callbacks are dropped to protect rapid channel zapping.
  5. **Missing XMLTV `stop` defaults** to `start + 30 minutes` and timezone offsets accept both spaced and compact forms (`+0530`, `+05`).
- **Consequence:** Deterministic remote behaviour (one layer per BACK, one channel action per arrow), no player recovery races, and tolerant EPG ingestion. EPG timeline virtualization (BUG-008) is explicitly deferred: it needs a dedicated windowing + 2-D focus design and is tracked in `docs/BUGS.md`.

### ADR 009: Single lockfile policy (npm)
- **Context:** The repository currently ships two lockfiles — `package-lock.json` (npm, matches the installed `node_modules`) and a stale `bun.lock`. New guardrail tooling (Vitest, Playwright, ESLint) was installed with npm to avoid a third lockfile.
- **Decision:** npm is the single package manager. `package-lock.json` is authoritative. `bun.lock` is stale and should be removed, but is left in place for a separate, explicit cleanup.
- **Consequence:** CI uses `npm ci`. Copies of the older prompts that say `pnpm` should be read as `npm run` / `npx`. The architecture and guardrail docs are [`ARCHITECTURE.md`](./ARCHITECTURE.md) and [`GUARDRAILS.md`](./GUARDRAILS.md).

### ADR 010: Capacitor native shell with mobile/TV product flavors
- **Context:** The player must ship as an installable Android TV / Google TV / Fire TV app and a phone/tablet app, without rewriting the React client and without introducing a server. The web app already owns focus, navigation, storage and playback.
- **Decision:**
  1. **Capacitor 7 wraps the existing bundle.** One web build (`dist/`) is the single source of truth; `npx cap sync android` copies it into the Android project. No web code forks per platform.
  2. **Two Gradle product flavors, one codebase.** `mobile` (touch, portrait allowed, leanback not required) and `tv` (leanback required, touchscreen not required, landscape, `LEANBACK_LAUNCHER` entry point, `Theme.AetherTv`). Per-flavor differences flow through `manifestPlaceholders` and the `src/tv/AndroidManifest.xml` overlay so `src/main/AndroidManifest.xml` stays single-source. Application ids: `tv.aether.iptv` (mobile) and `tv.aether.iptv.tv` (TV), letting both installs coexist on one device.
  3. **BACK is bridged, not duplicated.** Android delivers BACK to the Activity, so `@capacitor/app`'s `backButton` event is routed through the existing `dispatchBack()` funnel in `src/shared/input/nativeBackBridge.ts`. No second listener is registered and no raw key listener is added outside `src/shared/input` (Rule 8). When nothing consumed the press the app exits.
  4. **The shell stays thin.** `MainActivity` only sets immersive mode, keeps the screen awake, disables the media-user-gesture requirement (hls.js/mpegts.js autoplay), translates the remote OK button (`KEYCODE_DPAD_CENTER`) into `KEYCODE_ENTER` so the spatial-navigation engine's Enter activation fires on every remote, and gives the WebView focus so D-pad events reach the DOM. Playback logic remains in `src/services/player`.
  5. **Cleartext + mixed content stay allowed** via `network_security_config.xml` and `allowMixedContent`, because Xtream/M3U panels are commonly plain HTTP on private hosts.
  6. **Artwork is generated, not hand-exported** (`scripts/android-assets.py`): launcher icons, adaptive foregrounds, splash screens and the required 320×180 TV banner derive from the same brand colors as the M3 theme.
  7. **Release signing is external.** `android/keystore.properties` (gitignored) feeds `signingConfigs.release`; debug builds need no setup. WebView codec coverage is the known ceiling — a Media3/ExoPlayer engine behind the existing `PlayerEngine` interface is the follow-up if target boxes fail on TS/HEVC.
- **Consequence:** `npm run android:debug` / `android:release` produce four APKs (`aether-iptv-{mobile,tv}-{debug,release}.apk`) from one web build. Full instructions, verification commands and the device test matrix live in [`ANDROID.md`](./ANDROID.md).

### ADR 011: Soft keyboard (IME) on touch devices is a shell concern
- **Context:** BUG-018 — the mobile APK showed no soft keyboard for any text input. `MainActivity` set `webView.setFocusableInTouchMode(false)` unconditionally. That is required on TV (no touch; D-pad must own focus) but on a touch device it prevents the WebView from taking focus from a tap, so the WebView is never bound to the input method and Android raises no keyboard.
- **Decision:**
  1. The touch-vs-TV decision is **data, not code**: each flavor declares `resValue "bool", "aether_touch_device"` (`mobile` → `true`, `tv` → `false`) and `MainActivity` reads it for `setFocusableInTouchMode`.
  2. The IME must be able to resize the page: the single activity declares `android:windowSoftInputMode="adjustResize"`.
  3. The global `user-select: none` from the 10-foot shell is overridden for `input`, `textarea` and `[contenteditable='true']`, because some WebViews will not place a caret in an element that cannot select text.
  4. The behaviour is locked with an instrumented test (`MainActivityImeTest`) that launches the activity and asserts both the touch-mode focus value for the running flavor and the resize soft-input mode, since jsdom cannot observe native focus or the IME.
- **Consequence:** Phones/tablets raise the OS keyboard on tap while the TV build keeps touch-mode focus off. Any future flavor (e.g. a tablet-only build) only needs the boolean resource; no branching in `MainActivity`. The in-app virtual keyboard remains the TV path and a fallback everywhere.

### ADR 012: Theme variants must redefine every M3 token
- **Context:** BUG-019 — Settings offered Dark / AMOLED / Light, but Light rendered identically to Dark. `applyTheme()` correctly added `theme-light` to `<html>`, yet `src/index.css` only defined token blocks for `:root` (dark) and `html.theme-amoled`; with no `html.theme-light` block the dark values stayed in force.
- **Decision:**
  1. The class toggled by `applyTheme()` (`theme-light`, `theme-amoled`) is the single switch for a palette; CSS owns the values and components never branch on theme.
  2. A variant that changes surface tone must restate **every** `--md-sys-color-*` token the `:root` dark block declares, plus `color-scheme` so native controls and scrollbars follow. Partial overrides are allowed only for deliberate near-duplicates (AMOLED restates surfaces only, by design).
  3. Non-video surfaces use tokens (`surface-container-highest`, `outline-variant`, focus-ring token) rather than `bg-black/*` or `bg-white/*` alpha literals. Black-alpha remains acceptable only for scrims over the video plane.
  4. The parity rule is locked by `src/app/settingsStore.test.ts` (parses `src/index.css`, asserts the light block covers every dark token) and a Playwright assertion that the light body background is bright and distinct from dark.
- **Consequence:** Adding a theme variant without a full palette fails `npm test` instead of silently shipping a look-alike. Future variants must also be added to the `cases` table in that test.

### ADR 013: Navigation — permanent icon-only rail; labels via aria only; hints moved to content footer
- **Context:** The previous side drawer was `position: fixed` over the content, clipped hero text at the left edge, expanded on hover/focus into a ~256 px labelled panel (wasting ~230 px of a 10-foot screen) and crammed the wordmark plus a colour-key legend into the sidebar. It also relied on the library's inverse boolean polarity for arrow presses (BUG-001 class) and had no active-vs-focused distinction at 3 m.
- **Decision:**
  1. Replace the drawer with a permanent `NavigationRail` that lives **in normal layout flow** (`rail | content` flex row, never `position: fixed`), is exactly `--rail-width` wide and never expands. Content starts at the rail's trailing edge plus the standard safe-area padding, so the drawer's `ml-20` hack is gone.
  2. Icon-only: logo mark (no wordmark/subtitle), Home / Live TV / EPG Guide / Favorites / Search vertically centred, Settings pinned to the bottom. Icons are `<Icon/>` Material Symbols Rounded at `--rail-icon-size`; every item is a `--rail-item-size` square hit target whose accessible name comes from `aria-label` only. Active = `secondary-container` pill + filled icon + `aria-current="page"`; focused = 3 px `--md-sys-color-primary` ring + scale 1.06. Motion is limited to `transform`/`opacity` and honours `prefers-reduced-motion`.
  3. Focus rules live in the `NAV_RAIL` zone and use only `shared/focus` wrappers: LEFT enters on the active item (`preferredChildFocusKey`, `saveLastFocusedChild: false`); UP/DOWN stop at the ends (focus boundary for `left`/`up`/`down` plus `BLOCK_NAVIGATION` sentinels with a one-line reason each); RIGHT restores the last content element remembered by `src/shared/focus/contentFocusMemory.ts`; OK navigates on `onEnterPress` only and lands focus on the new screen's primary target; BACK closes overlays first, then focuses the rail.
  4. `FocusScope` was added to `shared/focus` because `useFocusable` reads its parent from `FocusContext` and the library does **not** provide that context automatically — without it a container's `preferredChildFocusKey`/focus memory is silently ignored (children register against the ROOT).
  5. The colour-key legend moved out of the rail into a slim `RemoteHintBar` at the bottom of the content area, gated by a new persisted `showRemoteHints` setting (default on) and naturally hidden on the player route. The shortcuts themselves are unchanged.
  6. The rail is not rendered on the player, onboarding or other fullscreen routes; pointer clicks still navigate and follow the existing `:focus-visible` behaviour.
- **Consequence:** No content is clipped or overlapped at 1280×720, 1920×1080 or 3840×2160 (asserted in `e2e/navigation-rail.spec.ts`); active and focused states are distinguishable at 3 m; the whole app is D-pad navigable and BACK ordering is preserved. Geometry is documented in [`DESIGN_TOKENS.md`](./DESIGN_TOKENS.md) and focus rules in [`TV_INPUT.md`](./TV_INPUT.md).

### ADR 014: Focus zones own their children; a D-pad stop is always a control
- **Context:** BUG-020 — the Settings screen was dead to the remote. `FocusZone` rendered a focusable `div` but never provided `FocusContext`, so its children registered against the ROOT. The library navigates strictly between *siblings* and only descends into a component's children when focus is set on that component, so a zone with root-level children was a stop of its own: focus landed on the container, which has no `tv-focus-target`/`tv-focused` styling, and every subsequent arrow press appeared to do nothing. The settings tiles compounded it by being raw `<button>` elements that never called `useFocusable`, and `Card isInteractive={false}` was still a focus stop. `e2e/dpad.spec.ts` could not see any of this because it only asserted `document.activeElement`, which a mouse click leaves on the rail.
- **Decision:**
  1. **`FocusZone` owns its children by default** (`ownsChildren` → `FocusScope` from `shared/focus`). This is the pattern ADR 013 (4) already prescribed for the rail; it is now the default for every zone. Because a zone with focusable children is only ever a *routing* node — `setFocus`/`smartNavigate` descend to the last-focused or nearest child — a zone is never the final focus target unless it has no focusable children at all.
  2. **`focusZone` is not a stop by accident.** `FocusZone` accepts `focusable={false}` for pure layout wrappers, and `Card` passes `focusable: isInteractive` so a non-interactive card can never be focused.
  3. **Anything the remote can reach must be a real control.** Styled non-button tiles are wrapped in the local `FocusableTile` (settings) or the matching `shared/ui` primitive, so every stop carries `tv-focus-target` + `tv-focused` and an `onEnterPress` handler. The settings tab row is a zone (entry target is the active tab tile, `SETTINGS_TAB_*`), and each card section is a zone with explicit `SETTINGS_SECTION_*` keys.
  4. **The guardrail asserts the property, not the mechanism.** `e2e/dpad.spec.ts` now requires that after every arrow press on every top-level screen the engine's `[data-focused="true"]` element exists and has `tv-focus-target` (and it polls first, because async screens such as the EPG settle their focus a moment later). `e2e/settings-dpad.spec.ts` walks the settings screen and asserts the same, plus OK activation.
- **Consequence:** Focus on every screen lands on a visible, activatable control, and flat root-level sibling sets no longer cause the geometry heuristics to jump between unrelated sections (DOWN in settings now walks section by section). New zones get the tree behaviour for free; a zone that intentionally stays flat must opt out and say why. Any future non-`tv-focus-target` focus stop fails `npm run e2e`.

### ADR 015: Focus-driven scrolling via a transform axis
- **Context:** Scroll position was a side effect of `useFocusable` calling `el.scrollIntoView({ behavior: 'smooth', block: 'nearest', inline: 'center' })` on every focus change. `block: 'nearest'` pinned focused cards to the screen edge, `behavior: 'smooth'` stacked animations on held keys, the Home hero was clipped mid-state, headings were cut off at the top, and a parent `overflow-x-auto` clipped the 3 px focus ring / `scale(1.04)` at the left edge. Longer screens (100k-channel lists, the EPG) were unvirtualized.
- **Decision:**
  1. **Scrolling is derived from focus and owned by `src/shared/scroll`.** The focus hook no longer scrolls. Scroller hooks observe the engine's `data-focused="true"` marker and compute an offset from the item's `data-scroll-index`/`row`/`col`/`x` (index math), then animate the content with a **transform** (`translate3d`) on a retargetable rAF tween. A new target retargets the in-flight tween; there is no queue, no `scroll-behavior: smooth`, and no `scrollTop` animation.
  2. **Focus line = 0.38.** Row-snap screens anchor the focused row's top at 38% of the viewport so the next row peeks; `focusLine` is a config token. Offsets clamp to `[0, content − viewport]`, so the first rows rest at the top and the last rows rest at the bottom.
  3. **Hero has two discrete states.** Expanded/collapsed are toggled with classes on a **single, non-remounting DOM tree** (branching the JSX dropped DOM focus to `<body>`), with only `opacity`/`transform` transitions. The row-snap re-anchors the focused row when hero metrics change.
  4. **Grids/lists use minimal scroll + index-math windowing.** Columns are derived from viewport width; `VirtualGrid` keeps the full content height for clamping and renders only visible rows plus overscan, so 100k items stay responsive. Held keys are throttled/accelerated in `src/shared/input`, and `PageUp`/`PageDown`/`CH±`/digits jump by rows.
  5. **The 3 px ring is never clipped.** Scroll content reserves `--focus-ring-pad`; a Playwright spec asserts the ring bounds stay inside the nearest clipping container at 720p/1080p/4K.
  6. **Scroll + focus memory** is module-level (survives the player/dialog/route unmount) and restored offset-first so the window renders the row before focus is set.
- **Consequence:** The focused item is always fully visible and ring-intact, row-snap screens rest on the focus line, held-key scrolling settles cleanly with no stacked tweens, restore is exact, and `aether/no-adhoc-scroll` plus `e2e/scroll.spec.ts` prevent regressions. Model and config are documented in [`SCROLLING.md`](./SCROLLING.md).

### ADR 016: Secrets and local files are ignored by category, not by accident
- **Context:** `.gitignore` had accreted ad-hoc entries (`node_modules/`, `dist/`, `coverage/`, `.env*`, `.DS_Store`) with duplicated test-artifact blocks and no coverage for editor noise, keys, cloud credentials, or IPTV data. Xtream Codes playlist URLs embed the username and password in the URL (`http://host/get.php?username=USER&password=PASS`), so a single `.m3u` dropped in the working tree is a credential leak — and `*.m3u8` is also the HLS playlist extension, so both must be ignored while sanitized fixtures stay committed.
- **Decision:** `.gitignore` is organised into commented sections — dependencies, build/tooling output (including Capacitor/Android native output and PWA/Workbox artefacts), tests and coverage, logs, editor/OS noise, secrets, IPTV data, local agent scratch files, and a final negation block. Secrets are ignored broadly: `.env` and every `.env.*` except `.env.example`; private keys and certificates (`*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `id_rsa*`, `id_ed25519*`); cloud/service credentials (`*credentials*.json`, `service-account*.json`, `.npmrc`, `.netrc`, `.aws/`, `.gcloud/`, `.firebase/`, `.vercel/`, `.netlify/`); and IPTV payloads (`*.m3u`, `*.m3u8`, `*.xmltv`, `*.epg.xml*`, `playlists/`, `xtream/`, `local/`, `private/`, settings/backup exports). Negations only re-include items the repository intends to keep: `.env.example`, both lockfiles, `src/test/fixtures/**`, a future `public/sw.js`, `AGENTS.md`, `README.md` and `docs/**`.
- **Consequence:** Untracked leaks are caught before `git add`, sanitized fixtures remain committable, and no currently tracked file matches an ignore rule (verified with `git check-ignore -v` over `git ls-files`). `.gitignore` is not a history cleaner: it does not affect already-tracked files, so a committed secret still needs rotation, `git rm --cached` and history rewriting (see `AGENTS.md` §5). Android keystore material (`android/keystore.properties`, `*.jks`) is ignored at both the root and the Capacitor shell level.

### ADR 017: Virtualized item sizes are measured, not hard-coded in px
- **Context:** BUG-022 — `ChannelGridCard`, `ChannelListItem`, `FavoriteCard` and `SearchChannelCard` were handed a fixed px height (`208`/`168`) that had to equal the scroller's `rowSize` for index math to hold, but every inner size (Tailwind spacing/typography) was authored in rem. `1rem` follows the viewer's font size (browser/Android TV font scaling), so above the default 16 px the content became taller than the box; because the card is a flex column, flex shrank the `h4`/`p` line boxes and `overflow-hidden` cropped the channel name and group. Even at 16 px the grid card was 2 px short. Raising the constant is not a fix: any px height is wrong for some font size, and making it rem-proportional is also wrong at small sizes (the icon's px floor dominates there).
- **Decision:**
  1. **Cards are content-sized with a rem floor.** They declare a rem `min-height` (uniform rows, no collapse when a field is absent) and never set a px height, so the rendered row is exactly as tall as the typography demands.
  2. **The scroller measures the real cell.** `useGridScroller` gained `measureItemHeight?: boolean`; when on, `useMeasuredItemHeight` reads the first rendered cell's `offsetHeight` on a layout pass (`ResizeObserver`, mount/resize only — never on the focus hot path, per [ADR 015](#adr-015-focus-driven-scrolling-via-a-transform-axis)) and `useGridScroller` returns the measured `itemHeight`/`rowSize` for `VirtualGrid`, `ScrollPositionIndicator` and row-jump math. The `rowSize` option is now only the first-paint fallback.
  3. **Measurement uses `offsetHeight`, not `getBoundingClientRect`.** The focused card's `scale(1.04)` transform must never feed back into the row pitch.
- **Consequence:** Channel names and group labels survive any root font size or browser zoom, the grid/list/row pitch always equals the real layout (no window/offset desync), and new virtualized grids follow the same pattern: rem `min-height` on the cell + `measureItemHeight: true`. Documented in [`SCROLLING.md`](./SCROLLING.md); regression coverage in `e2e/channel-cards.spec.ts`.

### ADR 018: EPG is a per-playlist, multi-source, streaming pipeline behind a repository
- **Context:** A playlist can carry thousands of channels and a 100 MB XMLTV file, EPG hosts routinely block CORS, Xtream URLs embed credentials, and the previous code had a dead `DOMParser` parser and an un-virtualized 30-channel guide stub. The guide must be accurate across time zones and never wipe existing data on a failed refresh.
- **Decision:**
  1. **Pure domain core.** `src/domain/epg` owns XMLTV time parsing (`time.ts`), channel↔XMLTV matching (`matching.ts`) and Now/Next (`nowNext.ts`). No React, no I/O, fully unit-tested.
  2. **Streaming ingestion.** `fetcher` streams the response (byte progress, `AbortController`, timeout), sniffs gzip by magic bytes (`1f 8b`) with `Content-Encoding`/extension only as a short-head fallback (so an already-decoded body is never double-decompressed), and classifies CORS/mixed-content/timeout into credential-safe errors. Parsing runs in a **lazy-loaded worker** with a hand-written tolerant SAX-style tokenizer (no `DOMParser`, no new dependency). Programmes outside the retention window (−1 d/+3 d) or for unmatched channels are discarded while streaming.
  3. **Multi-source, per playlist.** `epgSources` are merged by priority; a channel has one resolved `epgMapping` (`manual` always wins). Matching is tiered (exact `tvg-id` → normalized name with quality-tag stripping → conservative fuzzy with a required margin); ties are never auto-mapped.
  4. **Repository boundary.** All persistence is behind `EpgRepository` (Dexie implementation + in-memory fake). Per-channel programme writes are an atomic swap, pruning only deletes `stop < now`, and playlist/source deletes cascade. Screens never hold the full EPG in React state — they query channel + window.
  5. **Runtime owns scheduling.** `app/epgRuntime` drives a scheduler with one refresh per source, dedupe, capped exponential backoff, TTL stale-while-revalidate, offline pause/resume and a single `getNowNext(channelId, now)` selector.
  6. **Guide virtualization.** The timeline virtualizes rows (measured rem height) and the channel column, scrolls horizontally via `shared/scroll`, and pins the header/column. The Guide and the settings EPG panel are lazy chunks so the initial bundle is not burdened.
  7. **Credentials stay secret.** Xtream XMLTV URLs are masked in the UI and never reach logs, error text or caches; sanitized fixtures live in `src/test/fixtures/epg/`.
- **Consequence:** An existing playlist gains a guide by URL, header auto-detect, Xtream derivation or local file using only the D-pad; large files do not freeze the UI; a failed refresh keeps the old guide; and Now/Next plus the Guide are time-zone correct. Documented in [`EPG.md`](./EPG.md); coverage in the `domain/epg`, `services/epg` and guide/settings suites plus `e2e/epg-guide.spec.ts`.
